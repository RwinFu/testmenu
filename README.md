# کافه رُست — منوی موبایلی

منوی فارسی و راست‌به‌چپ، بدون وابستگی اجرایی به فریم‌ورک یا سرویس فونت خارجی. مشتری مستقیماً دسته‌بندی، جست‌وجو و قیمت‌ها (تومان) را می‌بیند. آیتم ناموجود با برچسب مشخص می‌شود. فونت وزیرمتن و مجوز آن در `assets/fonts/` قرار دارند.

## صفحه‌ها

- `index.html`: منوی مشتری؛ همیشه اطلاعات منتشرشده را نشان می‌دهد، نه پیش‌نویس مرورگر.
- `admin.html`: ویرایشگر منو، قیمت، موجودی، دسته‌بندی، اطلاعات کافه و ورود/خروج فایل.
- `index.html?preview=1`: پیش‌نمایش پیش‌نویس همان مرورگر.
- `qr.html`: چاپ QR برای آدرس `https://rwinfu.github.io/testmenu/`.

**مهم: این پنل یک ویرایشگر استاتیک است، نه پنل آنلاین با ورود امن.** اطلاعات آن فقط در مرورگر مدیر ذخیره می‌شود. برای تغییر منوی همهٔ مشتریان باید فایل خروجی منتشر شود. هیچ رمز یا توکنی در کد سمت کاربر قرار ندهید. برای مدیریت آنلاین با ورود و انتشار آنی، به بک‌اند دارای احراز هویت و پایگاه داده نیاز است؛ GitHub Pages به‌تنهایی این قابلیت را ندارد.

## استفاده از پنل و انتشار قیمت‌ها

۱. `admin.html` را باز کنید. آیتم را اضافه/ویرایش کنید یا موجودی را تغییر دهید.
۲. «مشاهده پیش‌نویس» را بزنید. این پیش‌نمایش خصوصیِ همان مرورگر است؛ لینک آن پیش‌نویس را به گوشی دیگر منتقل نمی‌کند.
۳. «دانلود برای انتشار» را بزنید. فایل `menu-data.json` را نگه دارید؛ پاک شدن داده‌های مرورگر، پیش‌نویس را حذف می‌کند.
۴. در مخزن، فایل هم‌نام را با خروجی جایگزین کنید و تغییر را پس از بررسی در `main` ادغام کنید.
۵. workflow انتشار، داده‌ها را اعتبارسنجی کرده و نسخهٔ همراه سایت را می‌سازد؛ پس از موفق شدن اجرای Actions، منو برای همه به‌روز می‌شود.

اگر حافظهٔ مرورگر بسته یا پر باشد، ذخیرهٔ پیش‌نویس ممکن نیست؛ پیام خطا نمایش داده می‌شود و می‌توانید از وضعیت فعلی خروجی بگیرید. فایل ورودی باید ساختار صحیح، شناسه‌های یکتا، دسته‌بندی معتبر، قیمت عددی صحیح نامنفی و تصویر از چهار فایل پوشهٔ assets داشته باشد.

## علت مشکل بارگذاری و تغییرات

- آخرین انتشار بررسی‌شده در مرحلهٔ `Configure GitHub Pages` با خطای `Resource not accessible by integration` هنگام تلاش برای ایجاد Pages متوقف شده بود. تنظیم `enablement: true` حذف شد؛ ایجاد اولیهٔ Pages با دسترسی مدیر انجام می‌شود، نه توکن محدود workflow.
- Pages مخزن اکنون با `build_type=workflow` موجود است. در صورت بازگشت خطای 404/مجوز، مدیر مخزن باید **Settings → Pages → Source: GitHub Actions** و مجوز Pages در Actions را بررسی کند.
- workflow فقط از `main` منتشر می‌کند؛ قانون محیط `github-pages` مخزن نیز برای `main` تنظیم شده است. تغییرات این شاخه تا زمان ادغام و انتشار موفق، روی آدرس اصلی نیستند.
- قبلاً شکست fetch یا دسترسی به localStorage می‌توانست کل منو را خالی کند. اکنون نسخهٔ همراه سایت وجود دارد، درخواست پس از پنج ثانیه متوقف می‌شود و خرابی دادهٔ مرورگر مانع نمایش نیست.
- اگر دریافت JSON در سایت ناموفق باشد، نسخهٔ همراه با پیام «برای اطمینان از قیمت روز بپرسید» نمایش داده می‌شود. این روش آفلاین‌کردن کامل سایت نیست؛ فایل‌های HTML/JS همچنان باید قابل دریافت باشند.

## اجرا و آزمون

Node.js 22 و Python 3:

```bash
npm ci
npm test
npm run build
npm start
```

`http://localhost:8000/` و `http://localhost:8000/admin.html` را باز کنید. سرور برای پیش‌نمایش روی `0.0.0.0` گوش می‌دهد.

برای تست مرورگر:

```bash
npx playwright install --with-deps chromium
npm run test:e2e
```

در محیط دارای Chromium نصب‌شده می‌توان `CHROMIUM_PATH=/path/to/chromium` داد. آزمون‌ها شامل دسته‌بندی، جست‌وجوی فارسی/عربی، حافظهٔ مسدود، خطای شبکه، افزودن/حذف، ذخیرهٔ قیمت، ورود/خروج فایل، جداسازی پیش‌نویس از منوی مشتری و عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۲۸۰ هستند.

اجرای مستقیم `index.html` از فایل نیز با دادهٔ همراه ممکن است. پس از ویرایش دستی JSON برای هماهنگی این حالت، `node scripts/build.mjs` را اجرا کنید. خروجی `_site/` در Git ذخیره نمی‌شود؛ workflow فقط فایل‌های عمومی را از آن منتشر می‌کند، نه ابزارها و آزمون‌ها.
