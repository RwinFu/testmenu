# کافه رُست — منوی دیجیتال با پنل مدیریت

منوی فارسی و راست‌به‌چپ برای اسکن QR سر میز. مشتری فقط منو را می‌بیند: دسته‌بندی‌ها، جست‌وجو، عکس، قیمت، توضیح و ترکیبات هر غذا. سفارشی ثبت نمی‌شود و سفارش را مشتری به ویتر می‌گوید. سمت کافه یک **پنل مدیریت** با رمز ساده هست که آیتم‌ها، قیمت‌ها، موجودی، دسته‌بندی‌ها و اطلاعات کافه را عوض می‌کند.

برای گوشی طراحی شده: دسته‌بندی‌ها موقع اسکرول در دسترس می‌مانند، جست‌وجو با یک لمس باز می‌شود و جزئیات هر آیتم تمام‌صفحه و قابل بستن با دکمه یا کلید Escape است. در مرورگرهایی که پشتیبانی می‌کنند می‌توان منو را از گزینهٔ «افزودن به صفحهٔ اصلی» به صفحهٔ خانهٔ گوشی اضافه کرد.

بدون فریم‌ورک و بدون سرویس خارجی. فونت وزیرمتن و مجوزش در `assets/fonts/` است و عکس‌ها در `assets/` قرار دارند.

## آدرس‌ها

| صفحه | کاربرد |
| --- | --- |
| `https://rwinfu.github.io/testmenu/` | منوی مشتری |
| `https://rwinfu.github.io/testmenu/admin/` | **پنل مدیریت** (رمز پیش‌فرض: **1234**) |
| `https://rwinfu.github.io/testmenu/#admin` | همان پنل مدیریت |
| `https://rwinfu.github.io/testmenu/?admin=1` | همان پنل؛ اگر `#` در برنامه‌ای مشکل داشت |
| `https://rwinfu.github.io/testmenu/admin.html` | تغییر مسیر به `#admin` |
| `https://rwinfu.github.io/testmenu/qr.html` | نسخهٔ چاپی QR منو |

لینک پنل عمداً در منوی مشتری نیست؛ آدرس `/admin/` را فقط برای خودت نگه دار.

## رمز پنل

- رمز پیش‌فرض `1234` است و از بخش **اطلاعات کافه → رمز مدیر** به عددی ۴ تا ۱۲ رقمی تغییر می‌کند.
- صفحهٔ ورود صفحه‌کلید عددی بزرگ دارد؛ با لمس رقم‌ها یا تایپ با کیبورد وارد شو.
- رمز به‌صورت هش FNV در `localStorage` ذخیره می‌شود، نه متن ساده.
- بعد از ۵ تلاش اشتباه، ورود ۳۰ ثانیه قفل می‌شود.
- نشست ورود در `sessionStorage` است و با بستن تب تمام می‌شود.

> **مهم:** GitHub Pages فقط فایل ایستا میزبانی می‌کند و سرور ندارد. این رمز فقط جلوی دست‌رسی روزمره را می‌گیرد؛ امنیت واقعی (چند کاربر، ذخیرهٔ ابری) به بک‌اند نیاز دارد.

## ویرایش و انتشار منو

1. در پنل، آیتم‌ها و قیمت‌ها را عوض کن. تغییرات همان لحظه در منوی همان مرورگر دیده می‌شوند.
2. از بخش **انتشار منو** فایل `menu-data.json` را دانلود کن.
3. فایل را در مخزن GitHub جای `menu-data.json` بگذار (ویرایشگر GitHub یا PR).
4. با ادغام در `main`، workflow صفحات سایت را می‌سازد و `menu-defaults.js` و `_site` را از همان فایل به‌روز می‌کند.

پنل نسخهٔ محلی را در مرورگر نگه می‌دارد؛ دکمهٔ «بازگردانی منوی منتشرشده» آن را پاک می‌کند. امکان «بارگذاری فایل» هم برای انتقال منو بین دستگاه‌ها هست.

## اجرا و آزمون

نیازمندی‌ها: Node.js 22 و Python 3.

```bash
npm ci
npm test          # آزمون داده، ذخیره‌سازی و build
npm run build     # خروجی عمومی در _site/
npm start         # http://localhost:8000 از _local-site/
npm run test:e2e  # آزمون مرورگر (Playwright)
```

## ساختار فایل‌ها

- `index.html` — پوستهٔ منوی مشتری + پنل مدیریت (یک صفحه، دو مسیر)
- `app.js` — رندر دسته‌ها و آیتم‌ها، جست‌وجو، صفحهٔ جزئیات و مسیریابی `#admin`
- `admin.js` — ورود با رمز، ویرایش آیتم‌ها و قیمت‌ها، دسته‌بندی‌ها، اطلاعات کافه و انتشار فایل منو
- `menu-store.js` — اعتبارسنجی، ذخیره‌سازی منو و رویدادهای هم‌زمان‌سازی
- `menu-data.json` — منوی منتشرشده (منبع اصلی) شامل ترکیبات هر غذا
- `menu-defaults.js` — نسخهٔ تولیدشده از `menu-data.json` (برای باز شدن مستقیم فایل)
- `style.css` — طراحی موبایل‌اول منو، جست‌وجو و جزئیات، پنل و صفحهٔ QR
- `manifest.webmanifest` / `assets/icon.svg` — مشخصات نصب روی صفحهٔ اصلی و آیکن منو
- `admin/index.html` — مسیر کوتاه `/admin/` برای ورود مدیر
- `qr.html` / `qr-menu.svg` — صفحهٔ چاپ QR
- `scripts/build.mjs` — اعتبارسنجی و ساخت `_site` و `_local-site`

## امنیت

- CSP سخت‌گیرانه، `no-referrer`، بدون اسکریپت یا استایل درون‌خطی، و escape همهٔ خروجی‌ها.
- داده‌های منو قبل از ذخیره اعتبارسنجی می‌شوند (شناسهٔ یکتا، قیمت صحیح، دستهٔ معتبر، ترکیبات متنی، تصویر فقط از `assets/`).
- CI روی PRها تست، audit و build را اجرا می‌کند و CodeQL هفتگی اجرا می‌شود.
