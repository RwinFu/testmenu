# کافه رُست — منوی موبایلی

منوی فارسی و راست‌به‌چپ، بدون فریم‌ورک یا سرویس فونت خارجی. مشتری دسته‌بندی‌ها، جست‌وجو و قیمت‌ها (تومان) را می‌بیند. فونت وزیرمتن و مجوز آن در `assets/fonts/` قرار دارند.

## صفحه‌ها و لینک‌های مدیریت

- `index.html`: منوی عمومی؛ دادهٔ منتشرشده را نشان می‌دهد و هیچ پیوندی به پنل ندارد.
- `https://rwinfu.github.io/testmenu/admin.html`: صفحهٔ دسترسی مدیر؛ فقط یک راهنما و پیوند به ویرایشگر تأییدشدهٔ GitHub است، نه پنل ویرایش عمومی.
- [ویرایش منوی منتشرشده در GitHub](https://github.com/RwinFu/testmenu/edit/main/menu-data.json): برای ثبت مستقیم تغییرات، ورود و دسترسی نوشتن در مخزن لازم است. کاربران بدون مجوز فقط می‌توانند تغییر را از طریق fork/PR پیشنهاد دهند.
- پنل گرافیکی واقعی (`admin.html` در سورس) فقط در build محلی `npm start` قرار می‌گیرد و در سایت عمومی منتشر نمی‌شود.
- `index.html?preview=1`: پیش‌نمایش پیش‌نویس همان مرورگرِ پنل محلی.
- `qr.html`: چاپ QR منوی عمومی.

## مرز امنیتی مهم

GitHub Pages فقط فایل‌های ایستا میزبانی می‌کند و ورود امن یا کنترل دسترسی سمت سرور ندارد. بنابراین build عمومی، پنل گرافیکی و `admin.js` را حذف می‌کند و مسیر `/admin.html` را با یک درگاه ساده به ویرایشگر GitHub جایگزین می‌کند. تغییر منتشرشده فقط با مجوزهای GitHub و ادغام به `main` ممکن است.

پنل گرافیکی محلی ورود ندارد و پیش‌نویس را فقط در `localStorage` همان مرورگر نگه می‌دارد؛ آن را روی هاست عمومی اجرا نکنید و هیچ رمز، توکن یا کلید خصوصی در کد سمت کاربر نگذارید. مخفی‌کردن لینک یا `noindex` به‌تنهایی امنیت ایجاد نمی‌کند. برای پنل آنلاینِ گرافیکی با ورود، به بک‌اند یا میزبانی دارای احراز هویت نیاز است.

## استفاده از پنل محلی و انتشار منو

۱. `npm ci` و سپس `npm start` را اجرا کنید.
۲. در پیش‌نمایش محلی، `/admin.html` را باز کنید و آیتم‌ها یا قیمت‌ها را ویرایش کنید.
۳. «مشاهده پیش‌نویس» را بزنید؛ پیش‌نویس به دستگاه دیگری منتقل نمی‌شود.
۴. «دانلود برای انتشار» را بزنید و فایل `menu-data.json` را نگه دارید.
۵. فایل را با ویرایشگر GitHub بالا به‌روز کنید و تغییر را در PR بازبینی کنید؛ پس از ادغام در `main`، workflow منوی عمومی را منتشر می‌کند.

پیش‌نویس با پاک‌شدن داده‌های مرورگر حذف می‌شود. فایل منو هنگام ورود و build اعتبارسنجی می‌شود: شناسه‌ها یکتا، قیمت عدد صحیح نامنفی، دسته‌بندی معتبر و تصویر محدود به فایل‌های مجاز `assets/` است.

## امنیت و GitHub

- CI روی PRها و `main` اجرا می‌شود: آزمون‌ها، `npm audit` و بررسی اینکه خروجی عمومی شامل پنل گرافیکی یا `admin.js` نباشد.
- CodeQL کد JavaScript را روی PRها و به‌صورت هفتگی بررسی می‌کند.
- Dependabot به‌صورت هفتگی به‌روزرسانی npm و GitHub Actions را پیشنهاد می‌دهد. Actionهای workflow به SHA کامل commit پین شده‌اند.
- صفحات سیاست CSP محدودکننده و `no-referrer` دارند. GitHub Pages امکان تنظیم دلخواه هدرهای HTTP یا محافظت رمزدار از یک مسیر را نمی‌دهد.
- برای enforce شدن بازبینی، مدیر مخزن باید در **Settings → Rules → Rulesets** ادغام PR، CI و CodeQL را اجباری و force-push را غیرفعال کند. این تنظیم با فایل‌های مخزن جایگزین نمی‌شود.

## اجرا و آزمون

نیازمندی‌ها: Node.js 22 و Python 3.

```bash
npm ci
npm test
npm run build
npm start
```

`npm run build` خروجی عمومی را در `_site/` می‌سازد؛ پنل گرافیکی در آن قرار نمی‌گیرد. `npm start` خروجی محلی جداگانه‌ای در `_local-site/` می‌سازد که برای پنل لازم است؛ آن را روی اینترنت عمومی میزبانی نکنید.

برای تست مرورگر:

```bash
npx playwright install --with-deps chromium
npm run test:e2e
```

آزمون‌ها اعتبارسنجی داده، جدایی خروجی عمومی/محلی، جست‌وجو، دسته‌بندی، ذخیره/ورود/خروج و اندازه‌های موبایل و دسکتاپ را بررسی می‌کنند.

## انتشار GitHub Pages

Workflow فقط از `main` منتشر می‌کند. اگر انتشار 404 یا خطای دسترسی داشت، مدیر مخزن باید **Settings → Pages → Source: GitHub Actions** و مجوزهای Pages را بررسی کند. آدرس منوی عمومی `https://rwinfu.github.io/testmenu/` است؛ رابط ویرایش گرافیکی عمداً در این آدرس میزبانی نمی‌شود.
