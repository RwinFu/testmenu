# کافه رُست — منوی QR با سفارش از سر میز

منوی فارسی و راست‌به‌چپ برای اسکن QR سر میز. طراحی موبایل‌محور و عکس‌محور است: مشتری دسته‌بندی‌ها را می‌بیند، دنبال غذا می‌گردد، عکس و قیمت را می‌بیند، روی کارت می‌زند تا **ترکیبات و جزئیات** را بخواند، تعداد را انتخاب می‌کند و سفارش را ثبت می‌کند. سمت کافه، یک **پنل مدیریت** با رمز ساده و صفحه‌کلید عددی، سفارش‌های تازه را زنده نشان می‌دهد و امکان مدیریت منو، دسته‌بندی‌ها، ترکیبات و اطلاعات کافه را می‌دهد.

بدون فریم‌ورک، بدون فونت یا سرویس خارجی. فونت وزیرمتن و مجوز آن در `assets/fonts/` است. عکس‌ها در `assets/items/` قرار دارند.

## آدرس‌ها

| صفحه | کاربرد |
| --- | --- |
| `https://rwinfu.github.io/testmenu/` | منوی مشتری |
| `https://rwinfu.github.io/testmenu/?table=5` | منو با شمارهٔ میز از پیش پر شده (برای QR هر میز) |
| `https://rwinfu.github.io/testmenu/admin/` | **پنل مدیریت** (رمز پیش‌فرض: **1234**) |
| `https://rwinfu.github.io/testmenu/#admin` | همان پنل مدیریت |
| `https://rwinfu.github.io/testmenu/?admin=1` | همان پنل؛ اگر `#` در برنامه‌ای مشکل داشت |
| `https://rwinfu.github.io/testmenu/admin.html` | تغییر مسیر به `#admin` |
| `https://rwinfu.github.io/testmenu/qr.html` | نسخهٔ چاپی QR منو |

لینک «ورود مدیر» در پایین منو هم هست. مسیر `/admin/` برای وقتی است که آدرس را مستقیم در مرورگر می‌زنی یا برای مدیر نشان می‌کنی.

## رمز پنل

- رمز پیش‌فرض `1234` است و از بخش **کافه → رمز مدیر** به عددی ۴ تا ۱۲ رقمی تغییر می‌کند.
- صفحهٔ ورود، صفحه‌کلید عددی بزرگ دارد؛ با لمس رقم‌ها یا تایپ با کیبورد وارد شو.
- رمز به‌صورت هش FNV در `localStorage` ذخیره می‌شود، نه به‌صورت متن ساده.
- بعد از ۵ تلاش اشتباه، ورود ۳۰ ثانیه قفل می‌شود.
- نشست ورود در `sessionStorage` است و با بستن تب به پایان می‌رسد.

> **مهم:** GitHub Pages فقط فایل ایستا میزبانی می‌کند و سرور ندارد. این رمز فقط جلوی دست‌رسی روزمرهٔ مشتری به فرم‌ها را می‌گیرد؛ امنیت واقعی (تأیید هویت، چند کاربر، ذخیرهٔ ابری سفارش‌ها) فقط با بک‌اند یا سرویس دارای احراز هویت ممکن است.

## سفارش‌ها و ذخیره‌سازی

- منو، سفارش‌ها، سبد و رمز در `localStorage` همان مرورگر ذخیره می‌شوند.
- پنل و منوی مشتری در همان تب/مرورگر با هم هم‌زمان به‌روز می‌شوند (`CustomEvent` + `BroadcastChannel`).
- تغییر منو، قیمت، موجودی و ترکیبات در پنل، بلافاصله در منوی مشتری همان مرورگر دیده می‌شود.
- وقتی مشتری از گوشی خودش سفارش می‌دهد، سفارش در همان گوشی ثبت می‌شود و در پایان یک **کد سفارش** می‌گیرد که باید به ویتر نشان دهد. برای رسیدن خودکار سفارش به دستگاه کافه به یک سرور مشترک نیاز است.
- راه‌حل بدون سرور: در **کافه → واتساپ کافه** شماره را با کد کشور (مثلاً `989121234567`) وارد کن؛ بعد از ثبت سفارش، دکمهٔ «ارسال سفارش در واتساپ» پیام آمادهٔ سفارش را برای کافه می‌فرستد.
- بازگردانی منو و پاک‌کردن سفارش‌ها در بخش «کافه → ابزارهای منو» است.

## انتشار تغییرات منو برای همه

پنل، نسخهٔ محلی را در مرورگر نگه می‌دارد. برای اینکه تغییر قیمت‌ها، آیتم‌ها و ترکیبات برای همهٔ مشتریان منتشر شود، `menu-data.json` را در مخزن به‌روز کنید (ویرایشگر GitHub یا PR). با ادغام در `main`، workflow صفحات، `menu-defaults.js` و `_site` را از همان فایل می‌سازد.

## اجرا و آزمون

نیازمندی‌ها: Node.js 22 و Python 3.

```bash
npm ci
npm test          # آزمون داده، ذخیره‌سازی، سفارش و build
npm run build     # خروجی عمومی در _site/
npm start         # http://localhost:8000 از _local-site/
npm run test:e2e  # آزمون مرورگر (Playwright)
```

## ساختار فایل‌ها

- `index.html` — پوستهٔ منوی مشتری + پنل مدیریت (یک صفحه، دو مسیر)
- `app.js` — رندر کارت‌های غذا، جزئیات و ترکیبات، سبد، ثبت سفارش و مسیریابی `#admin`
- `admin.js` — ورود با رمز و صفحه‌کلید، زنده‌سازی سفارش‌ها، ویرایش منو و تنظیمات
- `menu-store.js` — اعتبارسنجی، ذخیره‌سازی منو/سفارش و رویدادهای هم‌زمان‌سازی
- `menu-data.json` — منوی منتشرشده (منبع اصلی) شامل ترکیبات هر غذا
- `menu-defaults.js` — نسخهٔ تولیدشده از `menu-data.json`
- `style.css` — طراحی موبایل‌محور، کارت‌های عکس‌دار، شیت‌های پایین‌کشیدنی و پنل
- `admin/index.html` — مسیر کوتاه `/admin/` برای ورود مدیر
- `qr.html` / `qr-menu.svg` — صفحهٔ چاپ QR
- `scripts/build.mjs` — اعتبارسنجی و ساخت `_site` و `_local-site`

## امنیت

- CSP سخت‌گیرانه، `no-referrer`، بدون اسکریپت یا استایل درون‌خطی، و همهٔ خروجی‌ها escape می‌شوند.
- داده‌های منو و سفارش قبل از ذخیره اعتبارسنجی می‌شوند (شناسهٔ یکتا، قیمت صحیح، دستهٔ معتبر، ترکیبات متنی، تصویر فقط از `assets/`).
- CI روی PRها تست، audit و build را اجرا می‌کند و CodeQL هفتگی اجرا می‌شود.
- جزئیات بیشتر در [SECURITY.md](SECURITY.md).
